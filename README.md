# كوستر الجامعة

واجهة ويب عربية لإدارة حجوزات الحافلة الجامعية، مبنية باستخدام React وVite وتتصل بمشروع Supabase الحالي.

## التشغيل المحلي

1. ثبّت Node.js 18 أو أحدث.
2. نفّذ `npm install`.
3. انسخ `.env.example` إلى `.env.local` وأدخل `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`.
4. شغّل `npm run dev`.

## البناء والنشر

`npm run build` ينشئ الموقع الساكن في `dist/`. عند البناء في GitHub Actions يستخدم Vite المسار `/coaster-react-vite/` الملائم للمستودع الجديد على GitHub Pages؛ أما التشغيل المحلي فيستخدم `/`.

سير العمل `.github/workflows/pages.yml` يهيّئ GitHub Pages عبر Actions ثم يبني وينشر الموقع تلقائيًا عند كل دفع إلى `main`. يتضمن ملف سير العمل عنوان Supabase ومفتاح `publishable` العام فقط ليعمل البناء بلا أسرار Actions؛ لا تضع أبدًا مفتاح `service_role` ضمن ملفات أو متغيرات `VITE_*` لأنها تُضمّن في حزمة المتصفح.

ملفات PWA الثابتة (manifest، service worker والأيقونات) موجودة في `public/`. يستخدم التطبيق عقود الجداول وRPC وEdge Function الموجودة مسبقاً، لذا يلزم استمرار سياسات Supabase كما يتوقع التطبيق الأصلي.

## الميزات المضافة

- **تكرار امتلاء المقاعد:** يعرض تكرار امتلاء الذهاب والعودة في آخر ستة أيام مماثلة، إلى جانب عدد المقاعد المتاحة حاليًا للغد عندما تكون بيانات المقاعد موجودة. هذا وصف تاريخي، وليس احتمالًا معايرًا أو ضمانًا للتوفر.
- **حكاية الأسبوع:** تلخص مجاميع المقاعد خلال سبعة أيام حسب بغداد، دون أسماء الطلاب أو سجلات الحضور الفردية.
- **مراقبة الانطلاق:** يستطيع المسؤول ضبط موعد الانطلاق المتوقع، ويظهر تنبيه إداري فقط بعد عشر دقائق إذا كانت المشاركة متوقفة أو لم يتجدد موقع الحافلة لأكثر من 120 ثانية.
- **تذكير الوصول:** يحدد المسؤول نقطتي وصول الذهاب والعودة على الخريطة أو بالإحداثيات. يستطيع الطالب تفعيل تذكير ونص محليين على جهازه؛ يعتمد التذكير على موقع الحافلة المشترك ويعمل عندما تكون الصفحة مفتوحة ونشطة. لا يتتبع التطبيق موقع الطالب ولا يضمن التنبيه في الخلفية.
- **نبض الطريق:** يقارن وسيط مدة الرحلة التاريخي بالوسيط الأسبوعي للاتجاه نفسه. لا يعرض تقديرًا قبل تسجيل أربع رحلات مكتملة مماثلة على الأقل، ولا يمثل بيانات حركة مرور مباشرة أو موعد وصول مضمون.
- **دردشة الطلاب:** غرفة نصية مشتركة متاحة للمستخدمين المسجلين ذوي الاشتراك الفعّال وغير المنتهي؛ تقبل الرسائل حتى 500 محرف Unicode بعد حذف المسافات الطرفية، ولا تدعم الصور أو الملفات. يظهر اسم العرض ونص الرسالة للطلاب المؤهلين والمسؤولين، لذا يُرجى عدم نشر بيانات شخصية. يعاد التحقق من الصلاحية كل 30 ثانية، وتمسح الرسائل المحمّلة وتغلق قناة التحديث عند سحبها أو تعذر التحقق منها. يستطيع المسؤولون مراجعة الرسائل المبلّغ عنها وعدد البلاغات وحذفها، ولا تظهر هويات المبلّغين في لوحة الإدارة.

## إعداد دردشة الطلاب في Supabase

ترحيل `supabase/migrations/20261113_student_chat.sql` **يجب تطبيقه يدويًا** من Supabase SQL Editor بعد المراجعة والموافقة المنفصلة؛ لا يُطبّق التطبيق أو البناء الترحيل تلقائيًا. تظل الدردشة غير متاحة حتى تطبيقه.

## إعداد نبض الطريق في Supabase

ترحيل قاعدة البيانات `supabase/migrations/20261113_trip_runs.sql` **لم يُطبّق تلقائيًا**. لتفعيل تسجيل مدد الرحلات، راجع ملف SQL ثم طبّقه يدويًا مرة واحدة من Supabase SQL Editor. بعدها يستطيع المسؤول بدء التسجيل وإنهاؤه من أدوات الإدارة. الترحيل لا يخزن هوية الطالب أو المشغّل، ويمنع القراءة المباشرة لسجلات الرحلات؛ الواجهة الطلابية تستدعي دالة مجمّعة تعرض أعدادًا ووسيطات فقط. يلزم تسجيل أربع رحلات مكتملة على الأقل للاتجاه ويوم الأسبوع المقصود قبل ظهور تقدير.

## الاختبارات

شغّل `npm test` لتنفيذ اختبارات الوحدات واختبارات قاعدة البيانات المعزولة. يطبّق اختبار الدردشة ملف SQL على PGlite مؤقت داخل بيئة الاختبار فقط، ولا يتصل بـSupabase الحي. شغّل `npm run build` للتحقق من بناء الإنتاج.
