# حماية الأسرار ومنطق الأعمال — خطة التنفيذ

> هذه الخطة توثق العمل على مستودع `coaster-react-vite` ومشروع Supabase المرتبط به. لا تحتوي أسراراً. لا تُشفّر شيفرة الواجهة على افتراض أنها ستبقى مخفية: أي JavaScript يُحمّل إلى المتصفح يمكن تحليله.

**الهدف:** إبقاء أسرار الخادم خارج المتصفح، وفرض صلاحيات العمل على الخادم عبر RLS وRPC وEdge Functions، وتسجيل حالة الإنتاج بدقة.

## القيود ومعايير الأمان

- يسمح للواجهة فقط بإعدادات Supabase العامة الموثقة؛ لا يوضع service-role أو VAPID private key في `VITE_*` أو المصدر أو ملفات البناء.
- لا يُعدّ إخفاء زر المشرف أو التحقق في React حاجزاً أمنياً؛ التفويض يُفرض في PostgreSQL أو Edge Function.
- لا تُغيّر سياسات قاعدة حية أو grants أو إعدادات Auth خارج النطاق الموافق عليه. لا تُحذف بيانات كجزء من تعديل السياسات.
- افحص ملفات المشروع والتاريخ والأدوات من دون طباعة أي قيمة سرية. لا تفترض أن مخططاً غير موجود في المستودع آمن.
- أي Edge Function منشورة يجب أن تتحقق من JWT ودور المشرف على الخادم، وتعيد أخطاء عامة، وتتحقق من المدخلات وحجم الجسم.

## مراحل التنفيذ

### 1. جرد الأسرار وحدود الثقة

افحص `.env*`, `.gitignore`, Git history، Workflow النشر، خدمات Auth والطالب والمشرف والدردشة، وترحيلات Supabase. صنّف البيانات إلى إعداد عام، أو صلاحية مفروضة في قاعدة البيانات، أو سر خادمي، أو عنصر غير متحقق يحتاج فحص المخطط الحي. سجّل النتائج في `docs/security/assessment.md` من دون قيم مفاتيح.

### 2. حارس أسرار الواجهة

أضف `scripts/check-client-secrets.mjs` واختباراته. اسمح فقط بإعدادات Supabase العامة المعروفة، وارفض أسماء متغيرات `VITE_*` غير المعتمدة ومؤشرات مفاتيح الخادم أو المفاتيح الخاصة. اجعل الفحص يعمل في CI قبل البناء وبعده على `dist/`، وألا يطبع القيم المطابقة.

### 3. تدقيق سياسات Supabase

أنشئ `docs/security/supabase-policy-audit.sql` كاستعلامات قراءة فقط محدودة النتائج للسياسات والـACL وتعريفات الدوال، واختبر أنها SELECT فقط ومقسّمة بحدود واضحة. راجع الجداول والدوال الحية قبل أي تغيير. احتفظ بجدول `buses` محمياً بـRLS، ولا تضف له سياسات دون تحديد دقيق لمن يحتاج الوصول.

بعد موافقة المستخدم، أزل سياسة القراءة القديمة التي لا تربط الرسائل بمجموعة الطالب، وأوقف صلاحيات RPC الدردشة القديمة غير المقيدة بالغرفة. قيد استدعاء الدوال الحساسة إلى الأدوار الضرورية فقط، واختبر النتيجة من كتالوج PostgreSQL.

### 4. نقل/تأمين عملية الإشعارات

افحص مصدر Edge Function الحالية واسمها المنشور قبل تعديل العميل. أدرج المصدر الذي يمكن مراجعته في المستودع، وتحقق من JWT وملف المشرف النشط والمدخلات على الخادم، واستخدم الأسرار من `Deno.env` فقط. أعد أخطاء عامة، وحدّ من حجم الجسم، واستدعِ الـslug المنشور فعلياً. اختبر وحدات التحقق محلياً وافحص TypeScript بـDeno قبل النشر. لا ترسل اختبار push إلى جمهور حقيقي واسع؛ يلزم جمهور اختبار داخلي.

لا تنقل `admin_reset_password` إلى Edge Function بلا حاجة؛ إذا كانت RPC الحالية تفرض دور المشرف وتعالج كلمة المرور داخل PostgreSQL، فاحتفظ بها إلى أن يظهر سبب تقني موثق للتغيير. لا ترفع حد كلمة المرور أو تغيّر إعدادات Auth بتخمين؛ راجع توافق واجهة الإدارة وسياسة المشروع أولاً.

### 5. التحقق والنشر

شغّل `npm test`, و`npm run check:client-secrets`, و`npm run build`, وفحص Deno للدالة، و`git diff --check` وفحص الملفات الجديدة. راجع التغييرات المرحّلة، ادفع فقط إلى المستودع والفرع اللذين اعتمدهما المستخدم، ثم تحقق من GitHub Actions للـcommit نفسه. سجّل بوضوح أي إعداد أو اختبار بقي غير منفذ.

## حالة التنفيذ — 2026-11-13

- **الجرد:** اكتمل. لا توجد مؤشرات عالية الثقة لمفاتيح خدمة أو مفاتيح خاصة في نسخ Git التي فُحصت. إعدادات Vite المنشورة عامة بالتعريف؛ استخدامها آمن فقط مع RLS وصلاحيات قاعدة صحيحة.
- **فحص أسرار الواجهة:** أُضيف إلى `package.json` وWorkflow GitHub Pages قبل البناء وبعده، مع اختبارات للمفاتيح العامة المسموحة، وأسماء المتغيرات الحساسة، ومؤشرات مفاتيح الخدمة والمفاتيح الخاصة.
- **RLS على buses:** فُعّل في Supabase الحي، ولا توجد سياسات؛ الوصول المباشر محجوب حتى يحدد مالك المشروع السياسات المطلوبة. التغيير محفوظ في `supabase/migrations/20261113103057_enable_rls_public_buses.sql`.
- **عزل غرف الدردشة:** بعد موافقة صريحة، حُذفت `student_chat_messages_eligible_read` القديمة. تحققنا أن `student_chat_messages_room_read` وحدها بقيت. لم تُحذف أي رسائل. الترحيل محفوظ في `supabase/migrations/20261113110716_drop_legacy_student_chat_eligible_read_policy.sql`.
- **تقليص صلاحيات RPC:** سُحبت صلاحية `PUBLIC`, `anon`, و`authenticated` عن تواقيع الدردشة القديمة غير المقيدة بالغرفة ودوال الإدارة القديمة. سُحبت صلاحية `anon` من `is_admin()` مع بقاء التنفيذ للمستخدم المسجل، وسُحب التنفيذ المباشر من `handle_new_user()` مع بقاء trigger `auth.users` فعالاً. تحققت `has_function_privilege` من الصلاحيات بعد الترحيل. الترحيل في `supabase/migrations/20261113110941_revoke_legacy_rpc_grants.sql`.
- **Push Edge Function:** جرى استرجاع الدالة الحية `bright-task`، ومراجعة مصدرها، وتحسين التحقق من JWT ودور المشرف، وإخفاء تفاصيل الأخطاء، وفحص UUID وحجم الجسم. صُحح استدعاء العميل ليطابق slug. فُحص المصدر بـDeno، ونُشر إلى Supabase كالإصدار 5 مع `verify_jwt=true`. لم تُغيّر الأسرار. لم يُرسل إشعار اختباري للجمهور؛ يلزم جمهور داخلي مضبوط لإجراء ذلك بأمان.
- **نتائج التحقق المحلي وCI:** `npm test` نجح بـ85 اختباراً دون إخفاق؛ فحص الأسرار نجح للمصدر وملفات البناء؛ `npm run build` نجح مع تحذير Vite قائم عن استيراد Supabase ديناميكياً وثابتاً؛ `deno check` نجح؛ وفحوص whitespace وسلامة الملفات نجحت. نجحت أيضاً بوابة GitHub Actions (الاختبارات، build، وفحص الأسرار قبل/بعد build) للـcommit `a0ca0d00c8ca11146a34a166b5a4ef3fde7c5d1a`.
- **ما لم يتغير:** لم تُضف سياسات لـ`buses`. إعداد حماية كلمات المرور المسرّبة في Supabase Auth بقي غير مفعّل؛ موصل Supabase لا يوفر إدارة هذا الإعداد، ولوحة التحكم طلبت تسجيل دخول. حد إعادة تعيين كلمة المرور الأدنى في RPC ما زال ستة أحرف، ولم يُغيّر دون مواءمة الواجهة والسياسة.
