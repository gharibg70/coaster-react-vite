# توحيد ملخص الطالب وتحسين إشراف الدردشة — خطة التنفيذ

> **For agentic workers:** نفّذ المهام حسب ترتيبها، واستخدم خطوات الاختبار المذكورة، ولا تطبق SQL على قاعدة حية.

**الهدف:** إزالة تكرار معلومات المقاعد وجمع ملخصات الطالب في بطاقة واحدة، وإضافة حذف آمن للرسائل من سجل الدردشة والبلاغات.

**البنية:** غلاف `StudentInsights` يجمع توقع الإشغال وحكاية الأسبوع وRoad Pulse؛ يحتفظ التوقع التاريخي بمحتواه لكن يتوقف عن تكرار المقاعد المتاحة حاليًا، ويجلب Road Pulse البيانات مرة واحدة للاتجاهين. يستخدم مشرف الدردشة RPC الحذف المقيد بالغرفة الموجود أصلًا، مع تأكيد وتحديث واجهتي السجل والبلاغات بعد النجاح.

**التقنيات:** React، Supabase RPC، CSS، Node.js test runner، React server renderer.

**المواصفات:** `docs/superpowers/specs/2026-11-13-student-insights-chat-moderation.md`

## القيود العامة
- لا تغيّر منطق تأكيد الحضور أو صلاحيات الطلاب.
- اعرض المقاعد الحالية مرة واحدة قرب خيارات الحجز؛ اجعل التاريخي منفصل المعنى داخل البطاقة الموحّدة.
- اجعل Road Pulse طلبًا واحدًا لكلا الاتجاهين، مع حالات مستقلة للتقدير/نقص البيانات.
- استخدم `admin_delete_student_chat_message` مع `p_room` و`p_message_id`، ولا تضف SQL migration.
- لا تسمح بحذف دون تأكيد ولا بتحديث محلي متفائل عند فشل RPC.

## نقاط المراجعة والاختبارات
1. يجب أن يبقى عدّ المقاعد مع خيارات الحجز وأن يبقى تعطيل الخيار الممتلئ كما هو؛ اختبر ذلك/راجع التكامل.
2. يجب أن تظهر كل من «تكرار امتلاء المقاعد» و«حكاية الأسبوع» و«نبض الطريق» مرة واحدة، وأن يعرض Road Pulse الذهاب والعودة من قراءة واحدة.
3. يجب ألا يظهر تقدير قديم بعد تغيير `serviceDate` أو `routeId`، وتبقى حالات الخطأ/إعادة المحاولة مفهومة.
4. حذف رسالة غير مبلغ عنها من سجل المشرف وحذفها من البلاغات يمرران الغرفة نفسها؛ خطأ RPC يبقي الرسالة/البلاغ ظاهراً ويعرض خطأ.
5. تبديل الغرفة أثناء الحذف لا يحدّث الغرفة الجديدة بنتيجة قديمة، ولا تتسرب هوية المبلّغ.

### المهمة 1: توحيد ملخص الطالب

**الملفات:** `StudentView.jsx`، `ForecastCard.jsx`، `WeeklyStory.jsx`، `RoadPulse.jsx`، `styles.css`، مكوّن جديد `StudentInsights.jsx`، واختبارات واجهة/وحدات ملائمة.

- أضف `StudentInsights` مرة واحدة إلى الصفحة الرئيسية، وضمّن الأقسام الثلاثة داخله دون بطاقات متداخلة.
- أزل عرض المقاعد الحالية من `ForecastCard` مع إبقاء اتجاهي التوقع التاريخي.
- اجعل `RoadPulse` يستقبل `serviceDate` فقط، يحمّل `get_road_pulse` مرة واحدة، ثم يحسب ويعرض outbound وreturn في القسم نفسه.
- اختبر بالـserver renderer العدد الفعلي لكل عنوان وبقاء اتجاهي Road Pulse. اختبر دوال التقدير لكل اتجاه. شغّل `npm test`.

### المهمة 2: حذف الرسائل من سجل الدردشة والبلاغات

**الملفات:** `ChatPanel.jsx`، `ChatModeration.jsx`، `chatModerationService.js`، `tests/chatModeration.test.js`، واختبارات مناسبة إضافية.

- عمّم واجهة خدمة الحذف إلى `deleteChatMessage(room, messageId)` و`deleteChatMessageRpcArgs(room, messageId)` مع إبقاء التحقق من الغرفة.
- أظهر زر حذف ذي اسم واضح للمشرف فقط في كل رسالة ضمن `ChatPanel`؛ استخدم `window.confirm`، وعطّل الزر للرسالة الجاري حذفها.
- استعمل الخدمة العامة نفسها من البلاغات ومن سجل الدردشة. بعد نجاح الحذف حدّث سجل الدردشة وقائمة البلاغات؛ عند الخطأ احتفظ بالحالة وأظهر التنبيه.
- اختبر معاملات RPC، الغرفة غير الصالحة، نجاح/فشل الخدمة، وعدم قبول استجابة قديمة بعد تبديل الغرفة.

### المهمة 3: بوابة الإصدار

شغّل `npm test`، ثم `GITHUB_ACTIONS=true npm run build` و`git diff --check`. راجع الفرق والصلاحيات قبل أي نشر. لا تطبّق SQL. ادفع إلى المستودع المعتمد فقط إذا كان النشر ضمن الإذن السابق، ثم تحقق من تشغيل CI والالتزام البعيد.
